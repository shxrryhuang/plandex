## 🏥 Critical bug fixes

- **Division by zero in `looksTextish`** (`shared/utils.go`). The rune-scanning loop consumed the input slice in place; after the loop `len(b)` was always 0, so the printable-ratio division produced `+Inf` (or `NaN`). The 90 % threshold was dead code — the function returned `true` for any valid UTF-8 with at least one printable rune. A `total` rune counter is now used for the divisor, with an explicit empty-input guard.

- **Missing `return` and pointer comparison in `InviteUserHandler`** (`handlers/invites.go`). Two bugs on the auto-add-domain guard: (1) `http.Error` was called but the handler did not return, so execution fell through and continued processing the invite. (2) `org.Domain == domain` compared two `*string` pointers (always unequal across separate allocations) instead of dereferencing them. The guard never fired. Fixed with a `return` and a nil-safe value comparison.

- **Panic in `fn(tx)` silently returned nil error** (`db/transactions.go`). `withTx` recovered panics via `defer`/`recover` and logged them, but the function had no named return value. After recovery the function returned the zero `error` — `nil` — telling the caller the transaction succeeded. The caller never saw the rollback. Changed to a named return `(retErr error)` and set it in the recover block.

## 🛡️ Nil-safety and bounds fixes

- **Nil user dereference in `execAuthenticate`** (`handlers/auth_helpers.go`). `db.GetUser` can return `(nil, nil)` when a user record is missing. The code checked `err != nil` but not `user == nil`; downstream accesses to `user.Id` and `user.Email` panicked. Added a nil check that returns 401.

- **Index out of range on `dbContexts[0]`** (`handlers/plans_exec.go`). `loadContexts` can return a non-nil response with an empty context slice. The code checked `res == nil` but not `len(dbContexts) == 0`; the index access panicked. Added an explicit length guard.

- **Nil `build` dereference in `onBuildFileError`** (`model/plan/build_finish.go`). `loadBuildFile` assigns `state.build` only on its success path (after `StorePlanBuild` and `ExecRepoOperation` both succeed). Every error return before that point leaves `fileState.build` nil. `onBuildFileError` then accessed `build.Error` unconditionally, panicking. Wrapped the block in an `if build != nil` guard.

- **Index out of range in diff hunk-header parsing** (`diff/diff.go`). `strings.Split(line, " ")[1:]` on a `@@` line with no trailing fields produced an empty slice; the immediate `lineInfo[0]` access panicked. Added a `len(lineInfo) == 0` guard that skips the malformed header.

## 🔧 Reliability and resource fixes

- **Temp-directory cleanup could be orphaned** (`diff/diff.go`). The deferred cleanup ran `os.RemoveAll` inside a goroutine. If the process exited immediately after `GetDiffs` returned, the goroutine had no chance to run. Changed to a direct `defer os.RemoveAll(...)`.

- **Cursor leak in `ListProjectsHandler`** (`handlers/projects.go`). `db.Conn.Query` returned `*sql.Rows` with no matching `Close`. A scan error inside the iteration loop caused an early return that leaked the database cursor. Added `defer rows.Close()`.

- **Build timing not recorded on error path** (`model/plan/build_whole_file.go`). `BuildWholeFileFinishedAt` was set only after the error check on `ModelRequest`, so the error path never recorded when the request finished. Moved the timestamp to immediately after `ModelRequest` returns, before the error branch.

- **Early context-cancellation check in `execPlanBuild`** (`model/plan/build_exec.go`). The goroutine proceeded through setup (parser initialisation, plan-state fetch) even when the plan context was already cancelled; cancellation was only caught later inside model calls. Added a `select` on `Ctx.Done()` right after the active-plan lookup.

## 🏷️ Naming correction

- Renamed `hasDuplicates` to `noDuplicates` in `UpsertCustomModelsHandler` (`handlers/models.go`). `CheckNoDuplicates()` returns `true` when no duplicates are found; the old name was the exact inverse of the value it held, making the surrounding logic difficult to reason about despite being accidentally correct.

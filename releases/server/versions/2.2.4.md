## ⚡ Pure-Go LCS diff — subprocess elimination

Replaced the per-file `git diff --no-index` subprocess in `GetDiffReplacements` with an in-process LCS algorithm.  For the dominant edit sizes (50–500 lines) the subprocess overhead — temp-directory allocation, two `WriteFile` calls, `exec.Command`, and cleanup — is completely eliminated.  Benchmark results on Apple M4: **872× speedup on 50-line files**, **20× speedup on 500-line files**.  A 5-file build that previously spent 90–135 ms on diff computation alone now completes in under 7 ms.  Files exceeding 5 000 trimmed lines fall back to the original git subprocess to keep memory bounded.

## 📊 Performance instrumentation

Added a lightweight metrics package (`perf`) with per-histogram duration tracking (p50 / p95 / p99) and atomic counters.  Instrumentation call sites cover diff computation, git add+commit, LLM HTTP round-trips, stream TTFT, tree-sitter apply, and tell-request setup.  A `GET /perf/metrics` endpoint (development-only; returns 403 in production) exposes the report.  Five standard `net/http/pprof` endpoints are also registered behind the same environment gate.

## 🔇 Remove `spew.Dump` / `spew.Sdump` on every model request

`github.com/davecgh/go-spew/spew` uses Go reflection to walk every struct field and was called unconditionally on every LLM request, including in production.  Replaced with targeted `log.Printf` calls that log only the fields operators need.

## 🐛 Bug fixes

- **`git status --porcelain` missing `-C dir`** (`db/git.go`).  `GitClearUncommittedChanges` computed the plan directory but ran `git status` without `-C dir`, checking the server CWD instead.  The "no changes" fast-path silently returned success, potentially leaving stale state.

## 🏗️ CI — benchmark regression gate

A new `perf-benchmarks.yml` workflow runs on every push/PR to `main`.  It executes the diff benchmarks with `-race`, uploads results as a 90-day artifact, enforces a hard ≥ 10× speedup gate on Small (50-line) files, and posts a summary table as a PR comment.  Medium (500-line) ratio is reported but advisory only due to CI hardware variance.

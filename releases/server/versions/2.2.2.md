## 🛡️ Stream processor reliability fixes

Fixed three bugs in the tell-stream chunk processor (`bufferOrStream`) that handle converting `<PlandexBlock>` XML tags into markdown code fences for real-time streaming output:

- Stop-sequence detection when the sequence spans the content buffer and the current chunk. The split was incorrectly applied to the chunk alone, so sequences that started in a prior chunk were never found.
- Orphaned buffer flush: when a speculatively-buffered stop-sequence prefix turned out not to be a stop sequence (e.g. it was actually a `<PlandexBlock>` tag), the buffer was never prepended back into content before normal tag detection ran. The tag was invisible to the replacement logic.
- Opening-tag replacement guard: `replaceCodeBlockOpeningTag` was only entered when `fileOpen` was already `true`, but a full opening tag arriving via a flushed buffer has `fileOpen=false`. The guard has been widened and `fileOpen` is now set on a successful match.

## 🏥 Context leak fix in structured edit builder

`cancelBuild` (from `context.WithCancel`) was not deferred in `buildStructuredEdits`. The cancel function was only reachable through the `buildRace` error path; the successful auto-apply path and the early error return both exited without calling it, leaking the context and any goroutines it held open.

## 🔧 CI pipeline

Added `.github/workflows/go-test-lint.yml` with a matrix strategy running `gofmt`, `go vet`, and `go test` across all three modules (`app/cli`, `app/server`, `app/shared`). Triggers on push to `main` and on pull requests targeting `main`.

## 🧪 Test coverage restored

Removed debug `only`/`Only` flags from `TestBufferOrStream` and `TestReplyParser` that were silently skipping 33 test cases. The three stream-processor bugs above were discovered and fixed as a result. A copy-paste typo in one test case (`contentBuffer` ending with `<Plandex` instead of `<Pland`) was also corrected.
